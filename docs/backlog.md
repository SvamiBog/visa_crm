Все этапы, сроки и гейты — в [roadmap.md](roadmap.md).

Задачи идут по порядку. Каждая — отдельная ветка и PR с тестами. Отмечайте `[x]`, когда задача влита в main.

## Этап 0 · Фундамент (≈3 недели)

Гейт: тестовый второй визовик не видит чужих данных.

- [x] **0.1 Каркас репозитория.** Структура уже создана: FastAPI + React + Alembic + CI + Dockerfile + railway.json. Осталось: выполнить `uv sync` и `npm install`, закоммитить `uv.lock` и `package-lock.json`, прогнать `uv run pytest`, `uv run ruff check .` и `npm run build`, исправить, если что-то не сходится (каркас писался без доступа к реестрам пакетов и не запускался). Готово, когда CI зелёный, а `/api/health` отвечает локально.
- [ ] **0.2 Деплой на Railway** (отложен до первой частично рабочей версии, решение 2026-10-15)**.** Проект в регионе EU West: веб-сервис из Dockerfile, PostgreSQL с томом, окружения production и staging, включён PITR. Готово, когда staging открывается по домену Railway и `/api/health?db=1` возвращает `db: ok`. Инструкция по шагам — docs/deploy.md. `railway.json` у Railway устарел (Config as Code, работает до 2026-12-01): настройки задаём в панели, перенос на Infrastructure as Code — отдельно, если понадобится.
- [x] **0.3 Модель арендаторов.** Таблицы `tenants` (визовик = арендатор), `users` (роль: admin / specialist / employee), `tenant_id` во всех бизнес-таблицах, Row-Level Security в Postgres с `SET app.tenant_id` на запрос. Тест: запрос от визовика B не видит строк визовика A даже при прямом SQL через сессию приложения.
- [x] **0.4 Вход.** Логин по email и паролю (argon2), серверные сессии в httpOnly-cookie, выход, блокировка после 10 неудачных попыток. Флаг `must_change_password`: пока он стоит, доступен только экран смены пароля.
- [x] **0.5 Двухфакторный вход.** TOTP для админа и визовиков, коды восстановления. Включение обязательно после первой смены пароля.
- [x] **0.6 Админка: визовики.** Админ создаёт визовика (имя, email, базовая валюта, налог), система выдаёт временный пароль; список визовиков, блокировка, переключатели модулей.
- [x] **0.7 Сотрудники.** Визовик приглашает сотрудника, выбирает его модули и (опционально) кейсы. Проверка прав на уровне API. _Выбор кейсов — вместе с 1.4._
- [x] **0.8 Журнал действий.** Неизменяемая таблица событий: кто, когда, что открыл или изменил (в том числе показ пароля из сейфа). Экран журнала для визовика (свои события) и админа (все). _Показ пароля из сейфа пишется вместе с сейфом (1.7)._
- [x] **0.9 Шифрование сейфа.** AES-GCM, ключ визовика зашифрован мастер-ключом `VAULT_MASTER_KEY`; функции encrypt/decrypt с тестами, ротация мастер-ключа описана в docs. _Ротация — docs/operations.md._
- [x] **0.10 i18n и оболочка интерфейса.** RU/EN, переключатель языка, меню кабинета и админки, выбранный стиль интерфейса (см. docs/prototype/Styles.dc.html) как тема. _Сделано: RU/EN с запоминанием выбора, меню кабинета и админки. Стиль A — основной; B, C и D каждый пользователь выбирает в «Настройках», выбор хранится в учётной записи._
- [ ] **0.11 Бэкапы.** Cron-сервис: ежедневный `pg_dump` во внешнее S3-хранилище в ЕС, проверка восстановления описана в docs. *Отложено до момента, когда сервис полностью в работе (см. decisions.md); до этого — встроенные снимки Railway.*

## Этап 1 · Ядро CRM (≈11 недель)

Гейт: все новые кейсы ведутся только в системе. Спецификация — docs/clients-module.md, экраны — docs/prototype/.

Карточки и картотека (4 недели)
- [x] **1.1 Справочники-основа:** страны и правила записи (общий, ведёт админ), цели визы, каналы прихода, партнёры с условиями, регистраторы с прайсом, предоплаты, валюты и налоги. _Сделано: страны и правила записи (админка «Страны и правила», раздел визовика «Страны и визы», начальные данные для Беларуси из PRD) и справочники визовика (раздел «Справочники»: цели, каналы, партнёры с условиями по странам, регистраторы с прайсом, предоплаты, валюты платежей). Системы и требования к паролям — вместе с сейфом (1.7), праздники — с рассылками (этап 4)._
- [ ] **1.2 Контакт:** карточка, поиск по имени, телефону, Telegram; защита от дублей по телефону; лента заметок; согласие и договор (дата + файл в S3). _Сделано: раздел «Клиенты» — список с поиском, карточка, дубли по телефону, лента заметок, семья и связи, даты согласия и договора. Осталось: файлы согласия и договора — после выбора хранилища (docs/open-questions.md)._
- [ ] **1.3 Консультация:** анкета консультации с проверками (срок паспорта и т. д.), решение да / нет / думает, оплата; «Создать кейс» на каждого заявителя с группой подачи.
- [ ] **1.4 Кейс:** основные поля, где подаётся, этап, результат визы (структурированные поля), связь кейсов группы подачи.
- [ ] **1.5 Картотека:** вкладки «Все / В работе / Консультации / Думают / Архив», фильтры, список и канбан по этапам с перетаскиванием.

Очереди, сейф, брони, финансы (2 недели)
- [ ] **1.6 Очереди и попытки:** лист ожидания (идентификатор по типу страны, почта заявки, зал), заявка с окном 60 дней и повторы; виды «Очередь: страна».
- [ ] **1.7 Сейф учётных записей** с генератором паролей по правилам системы и журналом показов.
- [ ] **1.8 Брони:** отели с дедлайном бесплатной отмены, авиабронь клиента со сроком действия; вид «Брони: дедлайны».
- [ ] **1.9 Финансы кейса:** платежи в валютах с курсом НБ РБ (api.nbrb.by) на дату платежа, остаток, талон, выплата партнёру по условиям, налог НПД, прочие расходы, прибыль. Все суммы — Decimal, юнит-тесты на формулы.
- [ ] **1.10 Расчёты с регистраторами:** лента оплат и списаний, баланс аванса.

Главный экран и аналитика (2 недели)

- [ ] **1.12 Главный экран:** показатели, ближайшие подачи, воронка месяца, очереди, быстрые переходы.
- [ ] **1.13 Аналитика:** каналы (воронка и прибыль), консультации по месяцам, подачи и выдачи по странам, визовые центры, очереди, финансы, заявители.
