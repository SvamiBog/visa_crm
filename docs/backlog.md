## Этап 0 · Фундамент (≈3 недели)

Гейт: тестовый второй визовик не видит чужих данных.

- [x] **0.1 Каркас репозитория.** Структура уже создана: FastAPI + React + Alembic + CI + Dockerfile + railway.json. Осталось: выполнить `uv sync` и `npm install`, закоммитить `uv.lock` и `package-lock.json`, прогнать `uv run pytest`, `uv run ruff check .` и `npm run build`, исправить, если что-то не сходится (каркас писался без доступа к реестрам пакетов и не запускался). Готово, когда CI зелёный, а `/api/health` отвечает локально.
- [x] **0.2 Деплой на Railway** (отложен до первой частично рабочей версии, решение 2026-10-15)**.** Проект в регионе EU West: веб-сервис из Dockerfile, PostgreSQL с томом, окружения production и staging, включён PITR. Готово, когда staging открывается по домену Railway и `/api/health?db=1` возвращает `db: ok`. Инструкция по шагам — docs/deploy.md. `railway.json` у Railway устарел (Config as Code, работает до 2026-12-01): настройки задаём в панели, перенос на Infrastructure as Code — отдельно, если понадобится. _Сделано: staging (2026-10-16), стенды на каждый PR, production в Амстердаме — выкатывается после каждого мержа в `main`. Резервные копии production — с 2026-10-25: тариф Pro, снимки Daily, Weekly и Monthly и PITR. PITR не включается, пока образ базы закреплён на минорной версии (`postgres-ssl:18.6`), поэтому образ — на теге `:18`._
- [x] **0.3 Модель арендаторов.** Таблицы `tenants` (визовик = арендатор), `users` (роль: admin / specialist / employee), `tenant_id` во всех бизнес-таблицах, Row-Level Security в Postgres с `SET app.tenant_id` на запрос. Тест: запрос от визовика B не видит строк визовика A даже при прямом SQL через сессию приложения.
