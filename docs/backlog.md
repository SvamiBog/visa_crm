## Этап 0 · Фундамент (≈3 недели)

Гейт: тестовый второй визовик не видит чужих данных.

- [x] **0.1 Каркас репозитория.** Структура уже создана: FastAPI + React + Alembic + CI + Dockerfile + railway.json. Осталось: выполнить `uv sync` и `npm install`, закоммитить `uv.lock` и `package-lock.json`, прогнать `uv run pytest`, `uv run ruff check .` и `npm run build`, исправить, если что-то не сходится (каркас писался без доступа к реестрам пакетов и не запускался). Готово, когда CI зелёный, а `/api/health` отвечает локально.
- [x] **0.2 Деплой на Railway** (отложен до первой частично рабочей версии, решение 2026-10-15)**.** Проект в регионе EU West: веб-сервис из Dockerfile, PostgreSQL с томом, окружения production и staging, включён PITR. Готово, когда staging открывается по домену Railway и `/api/health?db=1` возвращает `db: ok`. Инструкция по шагам — docs/deploy.md. Настройки сборки и запуска — в панели Railway, у каждого сервиса; `railway.json` удалён 2026-10-26, Infrastructure as Code не используем (decisions.md). _Сделано: staging (2026-10-16), стенды на каждый PR, production в Амстердаме — выкатывается после каждого мержа в `main`. Резервные копии production — с 2026-10-25: тариф Pro, снимки Daily, Weekly и Monthly и PITR. PITR не включается, пока образ базы закреплён на минорной версии (`postgres-ssl:18.6`), поэтому образ — на теге `:18`._
- [x] **0.3 Модель арендаторов.** Таблицы `tenants` (визовик = арендатор), `users` (роль: admin / specialist / employee), `tenant_id` во всех бизнес-таблицах, Row-Level Security в Postgres с `SET app.tenant_id` на запрос. Тест: запрос от визовика B не видит строк визовика A даже при прямом SQL через сессию приложения.

Передача — момент, когда кейс стал «рассмотрение» или сразу «результат»; его записывает база. День удаления — дата передачи по часовому поясу визовика плюс 7 дней. Кейс вернули на «сбор документов» или «подачу» — срок снят, файлы остаются; передали снова — 7 дней заново. Если день подачи прошёл, а этап не сменили, файлы ждут, пока визовик переведёт кейс. Файл, добавленный после передачи (например, для апелляции), живёт 7 дней со своей загрузки. Отсрочки нет; «Отложить на 30 дней» у паспортных данных (2.8) файлы не держит. За 2 дня до удаления в «Требует внимания» — пункт по каждому кейсу с файлами: кейс, дата, число файлов; кнопок «Отложить» и «Удалить сейчас» нет, «Готово» прячет пункт. В блоке «Документы» кейса — «Файлы удалятся ДД.ММ». Удаляет сам сайт, при запуске и каждые 6 часов, тем же циклом, что паспортные данные; повтор и перезапуск безопасны. В журнале — удаление без автора, с идентификаторами и числом файлов. Удаление файлов вместе с паспортными данными через 7 дней после решения (2.8) остаётся страховкой. Кейсам, которые к выпуску уже на рассмотрении или результате, миграция ставит передачу на момент выпуска. Работает там же, где страница клиента: при выключенном `CLIENT_PORTAL` ничего не удаляется и не показывается. Не входит: договоры и записи подписей (2.11), файлы согласия и договора в карточке, текст уведомления версии 2 (2.11).
