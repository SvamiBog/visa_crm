## Этап 0 · Фундамент (≈3 недели)

Гейт: тестовый второй визовик не видит чужих данных.

- [x] **0.1 Каркас репозитория.** Структура уже создана: FastAPI + React + Alembic + CI + Dockerfile + railway.json. Осталось: выполнить `uv sync` и `npm install`, закоммитить `uv.lock` и `package-lock.json`, прогнать `uv run pytest`, `uv run ruff check .` и `npm run build`, исправить, если что-то не сходится (каркас писался без доступа к реестрам пакетов и не запускался). Готово, когда CI зелёный, а `/api/health` отвечает локально.
- [ ] **0.2 Деплой на Railway** (отложен до первой частично рабочей версии, решение 2026-10-15)**.** Проект в регионе EU West: веб-сервис из Dockerfile, PostgreSQL с томом, окружения production и staging, включён PITR. Готово, когда staging открывается по домену Railway и `/api/health?db=1` возвращает `db: ok`. Инструкция по шагам — docs/deploy.md. `railway.json` у Railway устарел (Config as Code, работает до 2026-12-01): настройки задаём в панели, перенос на Infrastructure as Code — отдельно, если понадобится. _Сделано: staging (2026-10-16), стенды на каждый PR, production в Амстердаме — выкатывается после каждого мержа в `main`. Осталось: резервные копии production — на тарифе Hobby Railway их не делает, PITR тоже не включить (open-questions.md)._
- [x] **0.3 Модель арендаторов.** Таблицы `tenants` (визовик = арендатор), `users` (роль: admin / specialist / employee), `tenant_id` во всех бизнес-таблицах, Row-Level Security в Postgres с `SET app.tenant_id` на запрос. Тест: запрос от визовика B не видит строк визовика A даже при прямом SQL через сессию приложения.
- [x] **0.4 Вход.** Логин по email и паролю (argon2), серверные сессии в httpOnly-cookie, выход, блокировка после 10 неудачных попыток. Флаг `must_change_password`: пока он стоит, доступен только экран смены пароля.
- [x] **0.5 Двухфакторный вход.** TOTP и коды восстановления. ~~Включение обязательно после первой смены пароля.~~ С 2026-10-17 — по желанию для всех: включение и выключение в «Настройках».
- [x] **0.6 Админка: визовики.** Админ создаёт визовика (имя, email, базовая валюта, налог), система выдаёт временный пароль; список визовиков, блокировка, переключатели модулей.
- [x] **0.7 Сотрудники.** Визовик приглашает сотрудника, выбирает его модули и (опционально) кейсы. Проверка прав на уровне API. _Выбор кейсов — после ответа на вопрос 17 (docs/open-questions.md)._
- [x] **0.8 Журнал действий.** Неизменяемая таблица событий: кто, когда, что открыл или изменил (в том числе показ пароля из сейфа). Экран журнала для визовика (свои события) и админа (все). _Показ пароля из сейфа пишется в журнал с 1.7._
- [x] **0.9 Шифрование сейфа.** AES-GCM, ключ визовика зашифрован мастер-ключом `VAULT_MASTER_KEY`; функции encrypt/decrypt с тестами, ротация мастер-ключа описана в docs. _Ротация — docs/operations.md._
- [x] **0.10 i18n и оболочка интерфейса.** RU/EN, переключатель языка, меню кабинета и админки, выбранный стиль интерфейса (см. docs/prototype/Styles.dc.html) как тема. _Сделано: RU/EN с запоминанием выбора, меню кабинета и админки. Стиль A — основной; B, C и D каждый пользователь выбирает в «Настройках», выбор хранится в учётной записи._
- [ ] **0.11 Бэкапы.** Cron-сервис: ежедневный `pg_dump` во внешнее S3-хранилище в ЕС, проверка восстановления описана в docs. *Отложено до момента, когда сервис полностью в работе (см. decisions.md); до этого — встроенные снимки Railway.* _На тарифе Hobby встроенных снимков нет (проверено 2026-10-17): Pro или 0.11 раньше — вопрос в open-questions.md._
- [x] **0.12 Смена почты и тестовый стенд.** Смена почты для входа в настройках с кодом на новый адрес; отправка писем по SMTP (Mailpit локально и на стенде). Тестовый стенд на Railway: окружение staging и стенд на каждый PR с демо-данными (5 визовиков по ~300 клиентов), плашка «Тестовый стенд». Заголовки безопасности, проверка зависимостей и ZAP в CI. _Почтовый сервис для production — открытый вопрос; окружения в Railway включает владелец по docs/staging.md._
