# Эксплуатация

Команды запускаются в каталоге `backend` (на Railway — в shell веб-сервиса): `uv run python -m app.cli <команда>`.

## Первый администратор

```bash
uv run python -m app.cli create-admin you@example.com   # спросит пароль дважды
```

Регистрации на сайте нет: визовиков создаёт админ в админ-панели.

## Двухфакторный вход: потерян телефон

- **Визовик.** Админ в панели «Визовики» нажимает «Новый пароль»: выдаётся временный пароль, двухфакторный вход сбрасывается, при входе визовик подключит его заново.
- **Админ.** На сервере:
  ```bash
  uv run python -m app.cli reset-two-factor admin@example.com
  ```
  Все сессии этого пользователя закрываются; при следующем входе он подключает приложение заново.

## Мастер-ключ сейфа (`VAULT_MASTER_KEY`)

Мастер-ключ шифрует (AES-256-GCM) ключи визовиков и секреты двухфакторного входа. Каждый визовик получает свой случайный ключ данных при первом обращении к сейфу; в базе этот ключ лежит только зашифрованным мастер-ключом (`tenants.vault_key_encrypted`). Пароли клиентов шифруются ключом своего визовика. Поэтому выгрузка базы без мастер-ключа не раскрывает ни одного секрета, а секрет, скопированный в чужую строку, не расшифруется.

Код: `backend/app/core/crypto.py` (шифрование, мастер-ключ), `backend/app/core/vault.py` (ключи визовиков, перешифровка).

### Новый ключ

```bash
uv run python -m app.cli generate-master-key
```

Значение (32 случайных байта в base64) кладётся в переменную `VAULT_MASTER_KEY`: на Railway — в Variables сервиса, локально — в `backend/.env`. У production и staging разные ключи. Ключ хранится ещё и вне Railway (менеджер паролей владельца): если он потерян, зашифрованные данные не восстановить.

### Ротация

Когда: по расписанию (раз в год), при подозрении на утечку ключа, при уходе человека, который его видел.

1. Сгенерировать новый ключ (`generate-master-key`).
2. В переменных сервиса: `VAULT_MASTER_KEY_PREVIOUS` = старый ключ, `VAULT_MASTER_KEY` = новый. Задеплоить. Пока задан предыдущий ключ, приложение читает секреты обоими ключами, а новые шифрует новым — работа не прерывается.
3. Перешифровать всё новым ключом:
   ```bash
   uv run python -m app.cli rotate-master-key   # «Re-encrypted N secrets»
   ```
   Команда безопасна для повторного запуска: второй запуск перешифровывает 0.
4. Удалить `VAULT_MASTER_KEY_PREVIOUS`, задеплоить, проверить, что вход с двухфакторным кодом и показ пароля из сейфа работают.
5. Старый ключ уничтожить. Бэкапы, сделанные до ротации, по-прежнему открываются только старым ключом — храните его, пока не истекут эти бэкапы.
