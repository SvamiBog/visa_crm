# Пилот с визовиком (1.15)

Пилот — две недели ежедневной работы визовика в CRM вместо таблиц. Сначала она сама переносит свои таблицы, затем ведёт всех новых клиентов только в системе, а замечания превращаются в правки. Это гейт этапа 1: **все новые кейсы ведутся только в системе** ([roadmap.md](roadmap.md)).

Документ — по шагам: что подготовить до старта (раздел 1), как отрепетировать перенос на стенде (раздел 2), инструкция визовику по переносу (раздел 3), что проверить после него (раздел 4), как идёт пилот и когда он закончен (раздел 5). Ограничения на момент пилота — в разделе 6.

## 2. Репетиция на стенде

Перед переносом в production владелец проходит раздел 3 на стенде — на копии таблиц визовика или на вымышленной книге той же структуры. Книгу собирает команда:

```bash
cd backend && uv run python -m tests.pilot_book Репетиция.xlsx
```

1. Откройте стенд PR или `staging` (docs/staging.md) и войдите демо-админом.
2. Создайте нового визовика, чтобы кабинет был пустым. Войдите под ним.
3. Выполните раздел 3 по шагам и проверьте раздел 4.
4. Всё, что было непонятно или неудобно, запишите: это первые замечания пилота.

Тот же порядок проверяет автоматический тест `backend/tests/test_import_pilot.py`. Он загружает книгу целиком и проверяет, что каждый человек — одна карточка, долгов регистраторам нет, а повторная загрузка ничего не меняет.

## 3. Перенос таблиц — инструкция для визовика

**Перед импортом.**

- Загляните в «Справочники». Там уже есть каналы (Instagram, Сарафан, Партнёр, Друзья, Реклама) и цели (Туризм, Гостевая, Бизнес, Учёба). Переименуйте их под свои слова или выбирайте их при проверке.
- Регистраторов и партнёров можно завести заранее — с именами, как вы хотите их видеть.
- Лист «Почты» импорт не загружает. Внесите свои почты в «Сейф» → «Свои учётные записи», хотя бы почты букинга: тогда брони из листа «В работе» найдут свой аккаунт.

**Файл.** В Google Таблицах: «Файл» → «Скачать» → «Microsoft Excel (.xlsx)». Все листы окажутся в одном файле. Пароли из таблиц пока не удаляйте.

**Каждый лист** загружается одинаково:

1. Откройте «Импорт таблиц».
2. Выберите вид таблицы и файл, затем лист.
3. Проверьте колонки.
4. Нажмите «Проверить» и разберите незнакомые значения.
5. Нажмите «Загрузить».

**Порядок листов.** Сначала консультации: кейс откроется из консультации перед ним. Потом «Подача» — от старых лет к новым, тогда номера кейсов пойдут по годам. Последними — очереди, Франция и брони: они находят уже созданные кейсы.

**Колонки.**

- Большинство колонок угадывается само; выбор запоминается для следующих загрузок.
- Не загружаются: «Остаток» и «Прибыль» (CRM считает их сама), второй столбец «Дата подачи», «Акция», «Данные для заявки», «Дата создания кабинета», «Почта переадресации», «согласие».
- «Оплата за талон», «Мой расходник» и «Оплата моя посредникам» становятся талоном регистратора. Талон считается уже оплаченным, долга в расчётах не создаёт.
- «Оплата процента» становится выплатой партнёру, тоже уже выплаченной.

**Незнакомые значения.** Для каждого значения есть варианты:

- «Добавить в список».
- Выбрать существующее значение — «Инста» → Instagram.
- «Как «…»» — для двух написаний одного регистратора: «Наталья» и «Наталья В.».
- «Это партнёр» — для «Откуда»: PK doc, Latwy start, имена рекомендателей.
- «Не заполнять».

Выбор запоминается и действует во всех видах таблиц: решив «Наталья В.» в «Подаче», в очереди вы его уже не увидите.

**Отчёт.**

- «Пропущено» для строк итогов («ВЫРУЧКА», «Разница», строки с одними суммами) — это нормально. Строки, пропущенные из-за отсутствия ФИО, даты или страны, — проверьте.
- «Предупреждения» значат, что строка загружена, но одно значение — с догадкой или не перенесено:
  - дата без года — взят год из названия листа;
  - указан только месяц — взято 1-е число;
  - нет дня консультации — взято 1-е число месяца обращения;
  - несколько человек в ячейке;
  - талон без регистратора;
  - странная дата рождения;
  - город не найден;
  - почта вместо номера.

**Повторная загрузка.** Тот же лист можно загрузить снова — после правок в таблице или после ответа на вопрос. Строки обновятся, а не задвоятся. Не переименовывайте листы между загрузками: имя листа — часть «памяти» строки.

**После переноса.** Проверьте сейф: пароли открываются. Затем удалите пароли из Google Таблиц — CRM напомнит об этом.

## 4. Проверка после переноса

Визовик и владелец проверяют вместе. Найденное — замечания пилота (раздел 5).

- **Люди.** Найдите 10 знакомых клиентов. У каждого одна карточка, кейсы по годам, пометки «от …» в заметках.
- **Семьи.** Строки вида «А + супруга + сын» стали одной карточкой. Разделите их на отдельные карточки и объедините в группу подачи (вопрос 19).
- **Долг клиентов** на главной. Старые кейсы с «Остатком» в таблице попадут в долг. Решите по каждому: клиент реально должен, или доплату просто не записали в таблицу? Во втором случае внесите платёж в кейсе.
- **Аналитика.** Сравните прибыль по месяцам с колонкой «Прибыль». Учтите два отличия: CRM вычитает налог с официальных платежей (импортированные платежи — не официальные), а прибыль по месяцам пока считается по месяцу подачи, хотя визовик считает по месяцу оплаты (вопрос 18, задача 1.18).
- **Регистраторы.** Долгов нет: старые талоны отмечены «оплачен до CRM». Если какой-то талон на самом деле ещё не оплачен, снимите отметку в финансах кейса — он войдёт в расчёты.
- **Партнёры.** Выплаты из таблиц отмечены как выплаченные. Неоплаченные — исправьте в кейсе.
- **Очереди.** Польша, Латвия и Италия: в очереди сейчас те, кто должен быть. Снятые («Удалена из очереди …») сняты.
- **Франция.** Открытые заявки и их 60-й день (вопрос 21). Заявки с прошедшим 60-м днём сразу появятся в «Требует внимания»: закройте их или отправьте повторно.
- **Брони.** У каждой есть дата бесплатной отмены и аккаунт Booking.

## 5. Ход пилота

- **Срок** — две недели ежедневной работы. Все новые обращения, консультации и кейсы ведутся только в CRM; таблицы остаются только для чтения.
- **Замечания** визовик записывает коротко: что делала, что ожидала, что получилось. Владелец передаёт их в работу. Каждое замечание — пункт бэклога «1.15.n» и отдельный PR. Срочное (не может работать) — в тот же день, остальное — пачкой раз в несколько дней.
- **Раз в неделю** — короткий созвон: что неудобно и что вернула в таблицы.
- **Пилот закончен**, когда две недели подряд все новые кейсы ведутся в CRM без возврата к таблицам, а замечания закрыты или перенесены в бэклог. Тогда этап 1 закрыт: 1.15 отмечается в backlog.md, этап 1 в roadmap.md — ✅.

## 6. Ограничения на момент пилота

- **Семьи в одной ячейке** («А + супруга + сын») импорт не разделяет — вопрос 19.
- **Лист «Почты»** не загружается: свои почты вносятся в сейф вручную.
- **Города подачи** переносятся только для визовых центров, заведённых в справочнике (вопрос 14).
- **Угаданные колонки** — вопрос 20:
  - «Оплата моя посредникам» считается талоном;
  - два пароля во Франции сохраняются одной записью у почты;
  - «Акция» не загружается.
- **60-й день Франции.** В таблице — дата отправки + 59 дней, в CRM — + 60 (вопрос 21). Импорт берёт дату из таблицы, новые заявки считаются по правилу CRM.
- **Выплаты партнёрам из таблиц** считаются выплаченными — по аналогии с решением о талонах, ждёт подтверждения владельца.
- **Напоминания** только внутри CRM («Требует внимания»), без Telegram — этап 4.
