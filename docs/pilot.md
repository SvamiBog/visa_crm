# Пилот с визовиком (1.15)

Пилот — две недели ежедневной работы визовика в CRM вместо таблиц. Сначала она сама переносит свои таблицы, затем ведёт всех новых клиентов только в системе, а замечания превращаются в правки. Это гейт этапа 1: **все новые кейсы ведутся только в системе** ([roadmap.md](roadmap.md)).

Документ — по шагам: что подготовить до старта (раздел 1), как отрепетировать перенос до production (раздел 2), инструкция визовику по переносу (раздел 3), что проверить после него (раздел 4), как идёт пилот и когда он закончен (раздел 5). Ограничения на момент пилота — в разделе 6.

## 2. Репетиция до переноса

Перед переносом в production владелец проходит раздел 3 сам, на вымышленной книге той же структуры или на копии таблиц визовика. Две команды из `backend/` собирают вымышленную книгу и файл импорта, который должен сделать из неё ИИ по промту:

```bash
uv run python -m tests.pilot_book Книга.xlsx
uv run python -m tests.pilot_book_visacrm VisaCRM-импорт.xlsx
```

**Где репетировать.**

- **Копия таблиц визовика** — только на локальном стенде у себя на компьютере. В копии её клиенты, даже если часть данных изменена.
- **Вымышленная книга** — на локальном стенде или на стенде своего PR. У стенда PR свой пароль, он в логе стенда (staging.md, раздел 2).
- **Не на общем `staging`.** Туда входят тестировщики с общим паролем демо-админа, а админ открывает любой кабинет стенда. Копию настоящих таблиц не загружайте и на стенд PR: его база живёт в Railway, пока PR открыт.

**Локальный стенд.** Для репетиции заведите отдельную базу, чтобы потом удалить её одной командой. Из корня репозитория:

```bash
docker compose up -d
docker compose exec db createdb -U visacrm rehearsal
```

В `backend/.env` (если файла нет, скопируйте его из `backend/.env.example`) укажите эту базу: `DATABASE_URL=postgresql+asyncpg://visacrm:visacrm@localhost:5432/rehearsal`. Проверьте, что там есть `ENV=local` и ключ сейфа `VAULT_MASTER_KEY` (новый ключ печатает `uv run python -m app.cli generate-master-key`). Затем:

```bash
cd frontend && npm install && npm run build
cd ../backend
uv run alembic upgrade head
uv run python -m app.cli seed-demo --specialists 0   # только демо-админ
uv run uvicorn app.main:app
```

`seed-demo` напечатает пароль демо-админа `admin@demo.visacrm.test`. Если в `.env` задан `DEMO_PASSWORD`, пароль будет из него. Сайт откроется на http://localhost:8000.

**Репетиция.**

1. Откройте стенд и войдите демо-админом.
2. Создайте нового визовика, чтобы кабинет был пустым. Войдите под ним.
3. Пройдите раздел 3: отдайте ИИ `Книга.xlsx` (или копию таблиц визовика) с промтом и шаблоном, проверьте и загрузите его файл. Для вымышленной книги сравните его с `VisaCRM-импорт.xlsx`: там то, что ИИ должен был сделать. Ответы визовика, которые этот файл предполагает, — в начале `backend/tests/pilot_book_visacrm.py`.
4. Проверьте раздел 4.
5. Всё, что было непонятно или неудобно, запишите: это первые замечания пилота. Ошибки ИИ — правки промта (import-prompt.md).
6. После репетиции на копии таблиц удалите её следы. Остановите сайт и удалите базу: `docker compose exec db dropdb -U visacrm rehearsal`. Удалите копию книги и файл импорта от ИИ. В `backend/.env` верните прежнюю базу.

Автоматический тест `backend/tests/test_import_pilot.py` загружает `VisaCRM-импорт.xlsx` целиком и проверяет, что каждый человек — одна карточка, очереди и Франция нашли свои кейсы, долгов регистраторам нет, кейс 2023 года остался в 2023-м, а повторная загрузка ничего не меняет.

## 3. Перенос таблиц — инструкция для визовика

Таблицы в формат VisaCRM переводит ИИ по готовому промту, а CRM проверяет и загружает его файл. Формат — [data-format.md](data-format.md), промт — [import-prompt.md](import-prompt.md).

**Перед переносом.**

- Заведите направления в «Направлениях»: страны визы, страна подачи — Беларусь, как идёт запись и города. Каждая страна заводится отдельным направлением; похожие быстрее делать кнопкой «Копировать» (например, Германия, Австрия, Бельгия, Нидерланды, Люксембург, Словения с одинаковой записью). Где сейчас принимают (сайты операторов, 27.10.2026): Польша, Литва, Болгария — Минск, Брест, Гродно, Гомель, Витебск, Могилёв, Лида, Пинск, Барановичи; Венгрия — те же, кроме Витебска; Италия — Минск, Брест, Гродно, Гомель, Витебск; Латвия — Минск, Витебск; остальные страны и посольства — Минск. Города направлений попадут в шаблон, и ИИ возьмёт их оттуда.
- Загляните в «Справочники». Там уже есть каналы (Instagram, Сарафан, Партнёр, Друзья, Реклама) и цели (Туризм, Гостевая, Бизнес, Учёба). Переименуйте их под свои слова: ИИ возьмёт их из шаблона.
- Регистраторов и партнёров можно завести заранее — с именами, как вы хотите их видеть.
- В «Справочниках» → «Системы и пароли» должны быть почта, сайты визовых центров (VFS Global, TLScontact, BLS) и Booking: учётные записи из таблиц ложатся в них.

**Шаг 1. Шаблон и промт.** «Импорт таблиц» → «Скачать шаблон» и «Скопировать промт».

**Шаг 2. ИИ.** Откройте ИИ, который принимает файлы и выполняет код (например, ChatGPT или Claude), и вставьте промт. ИИ спросит, как работать:

- **«Файл делает ИИ».** Пришлите книгу целиком (Google Таблицы: «Файл» → «Скачать» → «Microsoft Excel (.xlsx)») и шаблон. Колонки с паролями удалите из копии заранее. Таблицы с данными клиентов уходят компании, которая делает ИИ.
- **«Данные остаются у вас».** ИИ получит только заголовки и несколько строк с вымышленными данными и напишет скрипт. Запустите его в Google Таблицах по подсказке ИИ и скачайте получившуюся таблицу как .xlsx. Пароли переносятся тоже.

ИИ разберёт каждый лист и спросит, что неясно. По книге первого визовика он наверняка спросит:

- что такое «Оплата моя посредникам» — только талоны регистратору или ещё и процент партнёру; что значат «Акция» и два пароля во Франции (вопрос 20);
- какого года лист «Латвия с 17.08» и какой страны «Список ЖО25»;
- как видно, кто подаётся семьёй (вопрос 19); один ли регистратор «Наталья», «Наталья В.» и «Наташа»; какие значения «Откуда» — партнёры.

**Шаг 3. Пробные карточки.** «Импорт таблиц» → выберите файл от ИИ. Файл ждёт на сервере, в картотеку пока ничего не попадает. CRM показывает первых пять клиентов файла такими, какими они станут в CRM. Всё верно — «Всё верно — обработать весь файл». Что-то не так — «Отменить», расскажите ИИ, что не так, и загрузите исправленный файл.

**Шаг 4. Проверка всего файла.** CRM обрабатывает весь файл, ничего не записывая, и показывает, что будет создано и изменено, и все карточки из файла.

- Ошибки и замечания названы листом, строкой и колонкой. Нажмите «Скопировать отчёт для ИИ» и вставьте его в тот же чат: ИИ исправит файл. В отчёте нет данных клиентов.
- Значения, которых нет в ваших списках: канал, партнёра, цель и регистратора можно добавить в список, взять существующее или не заполнять. Страну, город и систему сейфа исправляет ИИ.
- Откройте несколько знакомых карточек (поиск по ФИО или телефону): данные на месте, кейсы по годам, платежи, очереди. Отметки показывают, что файл добавит («новое») и что изменит («изменится»).

**Шаг 5. Загрузка.** «Подтвердить и добавить в картотеку». Отчёт останется в истории загрузок.

**Повторная загрузка.** Изменили таблицы или ответили на вопрос — попросите ИИ собрать файл заново и загрузите его. Записи узнаются по телефону, нику и ФИО, кейсы — по листу и стране: дублей не будет, а пустая ячейка ничего не стирает. Не переименовывайте листы между загрузками: имя листа — «Источник» кейса.

**После переноса.** Проверьте сейф: пароли открываются. Удалите пароли из Google Таблиц и сам файл импорта: в нём данные клиентов.

## 4. Проверка после переноса

Визовик и владелец проверяют вместе. Найденное — замечания пилота (раздел 5).

- **Люди.** Найдите 10 знакомых клиентов. У каждого одна карточка, кейсы по годам, пометки «от …» в заметках.
- **Семьи.** Члены семьи с именами — отдельные карточки и кейсы в одной группе подачи. Безымянные («+ супруг + сын») — заметка у основного клиента: заведите их карточки и добавьте кейсы в группу (вопрос 19).
- **Долг клиентов** на главной. Старые кейсы с «Остатком» в таблице попадут в долг. Решите по каждому: клиент реально должен, или доплату просто не записали в таблицу? Во втором случае внесите платёж в кейсе.
- **Аналитика.** Возьмите один месяц и сравните прибыль в «Аналитике» → «По месяцам» со своей таблицей. CRM считает как визовик, по приходам и оплатам (1.18): оплаты клиентов и зачёт консультации этого месяца минус талоны, выплаты партнёрам, налог с официальных платежей и прочие расходы этого месяца, каждая сумма по своей дате. Если месяц не сошёлся, проверьте по порядку:
  - **Даты старых талонов.** Талон из таблицы без своей даты встаёт на дату подачи кейса, а у кейса без даты подачи — на день загрузки файла. Такие талоны уйдут расходом в месяц загрузки: поправьте дату талона в финансах кейса.
  - **Налог.** CRM вычитает его только с официальных платежей, а платежи из таблиц загружены как неофициальные. Пока ставка в «Моей учётной записи» не задана, налог не вычитается совсем.
  - **Выплаты партнёрам.** Выплата входит в месяц, которым отмечена выплаченной. Не отмеченная выплаченной не вычитается ни в одном месяце: она в «К выплате партнёрам».
  - **Зачёт консультации.** Он входит в прибыль, только когда сохранён в финансах кейса: у нового кейса откройте «Стоимость и условия» и сохраните форму, до этого зачёт — лишь подсказка. Он считается в месяце оплаты консультации (без даты оплаты — в месяце консультации), поэтому ставьте дату оплаты в консультации. Прошлый месяц может вырасти задним числом: консультация оплачена в марте, кейс с зачётом открыт в июне — вырастет март. Так же прошлый месяц меняется, когда выплату партнёру отмечают прошедшей датой.
  - **Месяц в минусе** — не ошибка: талон оплачен в мае, клиент заплатил в июне — май −150, июнь +800.
  - Прибыль в строках «Каналы прихода» и «Партнёры» — другая: это прибыль кейсов целиком, а не деньги месяца.
- **Регистраторы.** Долгов нет: старые талоны отмечены «оплачен до CRM». Если какой-то талон на самом деле ещё не оплачен, снимите отметку в финансах кейса — он войдёт в расчёты.
- **Партнёры.** Выплаты из таблиц отмечены как выплаченные. Неоплаченные — исправьте в кейсе.
- **Очереди.** Польша, Латвия и Италия: в очереди сейчас те, кто должен быть. Снятые («Удалена из очереди …») сняты.
- **Франция.** Открытые заявки и их последний день окна. Он на день позже «60-го дня» в таблице: CRM считает дату отправки + 60 дней, и это верный срок. Истёкшие попытки закрыты своим последним днём. Заявки с прошедшим сроком сразу появятся в «Требует внимания»: закройте их или отправьте повторно.
- **Брони.** У каждой есть дата бесплатной отмены и аккаунт Booking.
- **Сверка файлом.** «Импорт таблиц» → «Выгрузка данных» без паролей даёт всё, что есть в CRM, одним файлом в формате VisaCRM, с теми же листами и колонками, что у файла от ИИ. Его удобно сверять со старыми таблицами фильтрами Excel или Google Таблиц. Исправления можно внести прямо в выгрузку и загрузить её обратно: строки найдут свои записи по кодам. Строку записи, которую после выгрузки меняли в CRM, импорт пропустит («изменено в CRM после выгрузки, выгрузите заново»).

## 5. Ход пилота

- **Срок** — две недели ежедневной работы. Все новые обращения, консультации и кейсы ведутся только в CRM; таблицы остаются только для чтения.
- **Замечания** визовик записывает коротко: что делала, что ожидала, что получилось. Владелец передаёт их в работу. Каждое замечание — пункт бэклога «1.15.n» и отдельный PR. Срочное (не может работать) — в тот же день, остальное — пачкой раз в несколько дней.
- **Раз в неделю** — короткий созвон: что неудобно и что вернула в таблицы.
- **Как идёт** (24.11.2026, ответы визовика — decisions.md → «Ответы визовика (2026-11-24)»): визовик уже работает в CRM и постепенно переносит старых клиентов. Старые таблицы через «Импорт таблиц» она ещё не загружала, сделает позже, поэтому перенос по разделам 3 и 4 и проверка 1.22 в production впереди. Правки пилота 1.15.1–1.15.15 она проверила в production 24.11.2026, всё в порядке.
- **Как идёт** (26.11.2026, ответы визовика — decisions.md → «Ответы визовика (2026-11-26)»): клиентов она вносит в CRM с прошлой недели, ноябрь ещё не перенесла. С 1 декабря 2026 все консультации и клиенты — только в CRM, поэтому две недели пилота считаются с 01.12.2026: этап 1 закрывается не раньше 15.12.2026.
- **Если пилот прекращается** или визовик переходит в другую систему: сначала «Выгрузка данных», потом «Удаление всех данных» в «Настройках». С паролями выгружайте, только если они нужны в новой системе: такой файл не отдавайте ИИ и удалите после переноса.
- **Пилот закончен**, когда две недели подряд все новые кейсы ведутся в CRM без возврата к таблицам, а замечания закрыты или перенесены в бэклог. Тогда этап 1 закрыт: 1.15 отмечается в backlog.md, этап 1 в roadmap.md — ✅.

## 6. Ограничения на момент пилота

- **Члены семьи без имён** («А + супруга + сын») становятся заметкой у основного клиента — вопрос 19.
- **Города подачи** переносятся, только если город есть в её направлении. Город старого кейса, которого в направлении нет (центр закрылся или сменился оператор), — предупреждение «значения нет в списке». Нужен такой город — добавьте его в направление и выключите: импорт его найдёт, а новые кейсы выбрать не смогут.
- **Угаданные колонки** («Оплата моя посредникам», «Акция», два пароля во Франции) ИИ уточняет у визовика — вопрос 20.
- **Выплаты партнёрам из таблиц** считаются выплаченными — по аналогии с решением о талонах, ждёт подтверждения владельца.
- **Напоминания** только внутри CRM («Требует внимания»), без Telegram — этап 4.
