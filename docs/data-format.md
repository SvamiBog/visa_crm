# Формат данных VisaCRM

Один формат на вход и на выход: CRM загружает только его и выгружает в нём же. Визовик держит у себя файл, который открывается в Excel, Google Таблицах и LibreOffice. Свои таблицы в этот формат визовик переводит с помощью ИИ — универсальный промт: [import-prompt.md](import-prompt.md).

Версия 1, утверждена владельцем 27.10.2026 (decisions.md → «Формат данных VisaCRM»). Делается в задаче 1.20 (backlog.md) и заменяет импорт с сопоставлением колонок (1.14, 1.16).

## Почему XLSX

| | XLSX | CSV | JSON |
| --- | --- | --- | --- |
| Открыть у себя | Excel, Google Таблицы, LibreOffice, Numbers | то же, но кодировка и разделитель ломаются (1251 / UTF-8, `;` / `,`) | только программисту |
| Несколько таблиц | листы одного файла | по файлу на таблицу | да |
| Даты и суммы | настоящие: сортировка, фильтры, суммы | текст | текст |
| Выпадающие списки | да | нет | нет |
| ИИ читает и пишет | да, кодом | да | да |

Значит, XLSX: один файл со всеми листами. CSV и JSON CRM не принимает.

## Общие правила

**Листы и колонки.** Названия листов и колонок постоянные, на русском или английском, как в интерфейсе. Регистр, «ё» и лишние пробелы не важны. Порядок листов и колонок не важен. Лишние листы и колонки пропускаются (в отчёте — предупреждение). Нужных листов может не быть: файл только с «Клиентами» — тоже файл. Первая строка листа — заголовки.

**Три вида колонок:**
- **ключи** — «Код клиента», «Код кейса» и другие: связывают листы между собой;
- **данные** — то, что CRM загружает;
- **справочные** (в выгрузке и шаблоне — серый заголовок) — ФИО клиента в дочерних листах, номер кейса, «Оплачено», «Остаток». Нужны, чтобы работать с файлом без ВПР. При загрузке не читаются, только сверяются: если «Код клиента» и ФИО в строке не сходятся, строка пропускается с предупреждением (защита от сдвинутых кодов).

**Значения — строго, без догадок.** Всё, что не по формату, — ошибка с листом, строкой и колонкой (без значения ячейки). Ошибка в обязательной колонке пропускает строку, в необязательной — только эту ячейку.

| Тип | Как писать | Нельзя |
| --- | --- | --- |
| Дата | ячейка-дата или текст `ДД.ММ.ГГГГ` (`ГГГГ-ММ-ДД` тоже) | «17.08», «октябрь 2024», «до 25.12» |
| Сумма | число, дробь через точку или запятую | «150 BYN», «150+50» |
| Валюта | код: BYN, EUR, USD, PLN…; пусто — базовая валюта кабинета | «руб.», «евро» |
| Да / нет | «да» / «нет» (yes / no) | «+», «✓» |
| Телефон | международный: `+375291234567` | «8 029…» |
| Telegram | ник: `@anna_v` | «в вайбере» |
| Постоянный список (этап, результат, решение…) | слово из листа «Справочник» | синонимы |
| Список визовика (канал, партнёр, цель, регистратор) | название; незнакомое CRM предложит добавить | — |
| Страна | название из справочника CRM или код (PL) | — |
| Город подачи | город визового центра этой страны из справочника | — |
| Несколько значений | через запятую: «Польша, Латвия» | — |

**Коды.**
- У каждого листа своя колонка кода: «Код клиента», «Код консультации», «Код кейса», на остальных листах — «Код». Без кода строки правка платежа в выгрузке добавила бы новый платёж, а не исправила старый.
- Код — любой текст до 64 знаков, уникальный на своём листе в пределах файла.
- В выгрузке коды — внутренние идентификаторы CRM (длинные, вида `3f2a9c1e-…`). С кодами ИИ их не спутать, поэтому строка из файла ИИ никогда не попадёт в чужую запись. Короткие номера («кейс 101») для этого не годятся: ИИ мог бы случайно написать такой же.
- В файле от ИИ коды любые, например «Подача25-17» (лист и строка источника). Они связывают листы одного файла и не обязаны совпадать между прогонами. «Код» на листах без ссылок на них можно не заполнять.

### Только в выгрузке и шаблоне

- **Справочник** — допустимые значения: страны, города подачи по странам, постоянные списки, а также каналы, партнёры, цели, регистраторы и системы сейфа этого кабинета. Из него берутся выпадающие списки. При загрузке не читается.
- **О файле** — кабинет, его базовая валюта, дата и время выгрузки, версия формата, «с паролями» или «без паролей».

## Повторная загрузка

**Как CRM узнаёт запись:**
1. По коду CRM (строки из выгрузки).
2. Иначе — по содержимому, как сейчас:
   - клиент — по телефону, затем по нику Telegram, затем по ФИО, если такая карточка одна;
   - консультация — клиент и дата;
   - кейс — клиент, страна визы, «Источник» и порядок таких строк;
   - запись в очереди — кейс и дата постановки;
   - заявка — кейс и номер попытки;
   - бронь — кейс и номер брони (без номера — место и заезд);
   - платёж — кейс, дата, сумма и валюта;
   - учётная запись — система и логин.
3. Не нашлась — создаётся.

Поэтому новый прогон ИИ по обновлённым таблицам не плодит дублей, даже если коды получились другими.

**Пустая ячейка:**
- В файле от ИИ или собранном вручную пустая ячейка ничего не меняет.
- В строке из выгрузки (у строки код CRM, в файле есть лист «О файле») пустая ячейка очищает поле: такая строка — снимок записи. Так правки, сделанные у себя, возвращаются в CRM целиком.
- Пароль пустой ячейкой не стирается никогда.

**Защита от устаревшего файла.** Если запись изменили в CRM после выгрузки, её строка не загружается: в отчёте — «изменено в CRM после выгрузки, выгрузите заново».

**Удаление.** Строка, убранная из файла, ничего не удаляет в CRM. Удаляют только в CRM.

**«Проверить» перед загрузкой — как сейчас.** Показывает, что будет создано и обновлено, ошибки по листам и строкам и незнакомые значения списков визовика. В отчёте нет данных клиентов, поэтому его можно отдать ИИ, чтобы он исправил файл.

## Выгрузка

- **Кто:** только визовик (владелец кабинета), не сотрудник.
- **Что:** все листы, «Справочник» и «О файле». Даты и суммы — настоящие, у списков — выпадающие значения, первая строка закреплена, справочные колонки серые. Пустая выгрузка — это и есть шаблон («Скачать шаблон»).
- **Без паролей** (по умолчанию): колонка «Пароль» пустая.
- **С паролями:**
  - галочка «С паролями» и подтверждение паролем аккаунта (и кодом 2FA, если включена);
  - в журнале — показ паролей с их количеством;
  - в имени файла — «с паролями»;
  - перед скачиванием — предупреждение: файл не отдавать ИИ и удалить после переноса;
  - паролем на открытие файл не шифруется: такой файл не открывают Google Таблицы, а пароли сейчас и так лежат в таблицах визовика открыто. Шифрование можно добавить позже.
- **Журнал:** одно событие на выгрузку с количествами, без данных клиентов.

## Не входит в версию 1

Файлы согласий и договоров (переносятся только их даты и номер), история виз и отказов из анкеты консультации, отметки чек-листа пакета, поездки 90/180, связи между клиентами, кто кому из сотрудников выдан, расчёты с регистраторами пачкой, журнал действий. Прибыли и налога кейса в файле нет: CRM считает их с тонкостями (налог — только с официальных платежей); из расчётов в «Кейсах» — только справочные «Оплачено» и «Остаток».
