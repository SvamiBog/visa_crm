# VisaCRM — контекст для Claude Code

CRM для визовика (специалиста, который ведёт клиентов «под ключ»: визы в ЕС, UK и другие страны). Сначала ею пользуется один визовик из Беларуси, затем, с этапа 3, она открывается другим визовикам как SaaS с индивидуальными условиями оплаты (админ ведёт календарь оплат). Сейчас идёт **этап 0 (фундамент)**, затем **этап 1 (ведение клиентов)**.

## Команды

```bash
docker compose up -d                     # локальный Postgres 16
cd backend && cp .env.example .env
uv sync                                  # зависимости (создаст uv.lock — коммитить)
uv run alembic upgrade head              # миграции
uv run uvicorn app.main:app --reload     # API на :8000, документация /api/docs
uv run pytest                            # тесты (нужен Postgres: создают базу visacrm_test, адрес — TEST_DATABASE_URL)
uv run ruff check . && uv run ruff format .
alembic revision --autogenerate -m "..."  # новая миграция (через uv run)
uv run python -m app.cli create-admin EMAIL  # первый админ платформы (другие команды — docs/operations.md)

cd frontend && npm install               # создаст package-lock.json — коммитить
npm run dev                              # UI на :5173, /api проксируется на :8000
npm run build                            # проверка типов + сборка в frontend/dist
```

## Архитектура и правила

- **Один веб-сервис.** FastAPI отдаёт `/api/*` и собранный фронтенд из `frontend/dist` с того же домена — так cookie-сессии работают без CORS. Деплой: `Dockerfile` + `railway.json`, Railway, регион EU West (Амстердам). На этапе 1 есть ещё только Postgres и cron-сервис (курсы валют, бэкап).
- **Мультиарендность с первого дня.** Визовик = арендатор (`tenant`). Каждая бизнес-таблица несёт `tenant_id`, доступ ограничен и в коде, и Row-Level Security в Postgres. Как это работает: в начале каждой транзакции сессия переключается на роль `visacrm_app` (`SET LOCAL ROLE`, у роли нет обхода RLS) и выставляет `app.tenant_id` (или `app.system = on` для входа и админки) — см. `app/core/db.py`: `scope_to_tenant` / `scope_to_system`. Сессия без области видимости не видит ни одной строки. Новая бизнес-таблица в миграции: колонка `tenant_id`, `ENABLE ROW LEVEL SECURITY` и политика `tenant_isolation` (образец — `enable_tenant_rls` в миграции 0001) плюс тест изоляции. Общие для всех данные (справочник стран и правил записи) — без `tenant_id`, правит только админ.
- **Роли:** `admin` (владелец платформы, админ-панель), `specialist` (визовик, все рабочие инструменты, без админских), `employee` (сотрудник визовика, только выданные модули и кейсы). Аккаунт визовика создаёт админ с временным паролем; флаг `must_change_password` пускает только на смену пароля. 2FA (TOTP) обязательна для админа и визовика. Доступ в API — зависимости из `app/api/deps.py`: `current_user` (пускает только после смены временного пароля и, для админа и визовика, включения 2FA; `app/core/two_factor.py`), `require_admin`, `TenantSession` (сессия БД в области визовика), `SystemSession` (вход и админка). Ошибки API — коды в `detail` (`invalid_credentials`, …), тексты к ним — `errors.*` в локалях.
- **Деньги.** Только `Decimal` / `NUMERIC(14,2)`, никаких float. Платёж хранит сумму, валюту, курс и сумму в базовой валюте визовика (сейчас BYN). Курс — Нацбанк РБ (api.nbrb.by) на дату платежа, редактируемый. Формулы прибыли, остатка, партнёрской выплаты и налога — в одном модуле с юнит-тестами (см. clients-module.md → «Финансы»).
- **Сейф паролей.** Пароли клиентов шифруются AES-GCM ключом визовика, который сам зашифрован `VAULT_MASTER_KEY` (`app/core/crypto.py`, `app/core/vault.py`: `get_tenant_key`, `encrypt_for_tenant`; ротация — docs/operations.md). Расшифровка только по явному действию, каждый показ пишется в журнал.
- **Журнал действий** — неизменяемый (только INSERT, триггер запрещает UPDATE/DELETE/TRUNCATE): кто, когда, что открыл или изменил. Писать через `app.core.audit.record(session, AuditAction.…, actor=…)` в той же транзакции, что и само действие; новое событие — значение в `AuditAction` и подпись `audit.action.*` в локалях. В `details` — только идентификаторы и короткие технические факты, без данных клиентов.
- **Персональные данные.** Сканы паспортов по умолчанию не храним (они остаются в Telegram у визовика). Храним согласие и договор (дата + файл в S3-хранилище в ЕС). Никаких персональных данных в логах, URL и сообщениях об ошибках.
- **i18n.** Ни одной строки интерфейса в коде — только ключи `t("...")` в `frontend/src/locales/{ru,en}.json`. Русский — основной, английский должен быть полным.
- **Время.** В базе — UTC (`timestamptz`), даты без времени — `date`. Отображение — в часовом поясе визовика (по умолчанию Europe/Minsk).
- **Справочники вместо хардкода.** Страны, правила записи (лист ожидания / заявка с окном / прямой слот / посольство, окно в днях, оператор ВЦ, тип идентификатора, приём апелляций), цели, каналы, регистраторы, партнёры, предоплаты, налоги — всё данные, а не константы.
- **Напоминания на этапе 1 — внутри CRM** (вычисляемый список «Требует внимания»). Telegram-ботов, оплаты от визовиков, модуля слотов и мобильного приложения на этапах 0–1 нет — не начинайте их без запроса.

## Как работать

- Берите следующую задачу из docs/backlog.md; одна задача — одна ветка и PR, в PR ссылка на пункт бэклога. После мержа отметьте пункт.
- Сначала тест на бизнес-правило (особенно деньги, сроки, права доступа), потом код.
- Схема БД меняется только миграциями Alembic; миграции не редактируем после мержа.
- Секреты — только в переменных окружения Railway и локальном `.env`, никогда в репозитории.
- Решение, которое меняет продукт, записывайте в docs/decisions.md; если вопрос не решён — добавьте в docs/open-questions.md и спросите, а не угадывайте.
- Документация и общение — на русском; код, имена, комментарии и коммиты — на английском.
